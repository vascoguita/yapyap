# Custom code moves into Settings, and the menus tidy up (#710)

Custom CSS and JavaScript is now a page of Settings, **Custom code**,
after Network and before Advanced, on every platform. Its window, its
menu item and their strings are gone; the IPC calls and the controller
stay as they were. The page is laid out as the rest of Settings: the
danger warning first, the switch in a card of its own (it changes the
draft, and applies when saved), then the account picker and the CSS and
JavaScript boxes in a second card, and Save with its status under them.
CSS still shows in WhatsApp as it is typed, and leaving the page, by
another page or by closing the window, takes back what was not saved.

Settings now guards unsaved edits as the Accounts window does
(`settings/leaving.ts`): picking another page in the list, a menu
opening another page (Help › Keyboard Shortcuts…, the assistant's menu),
and Escape all ask first with the shared discard prompt, and the address
stays on the page until the user discards.

The menus: File on Windows and Linux holds Settings…, Close Window and
Quit; on macOS File keeps Close Window alone, and the app menu loses
Custom CSS and JavaScript…. Close leaves the Window menu, which keeps
Minimize, macOS's Zoom and Bring All to Front, and Downloads…. Account,
Edit, View and Help are unchanged. Reviewed with the design plugin, which
brought the page title to sentence case like the other pages.
