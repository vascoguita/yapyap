# Suggestions answer the message the user replies to (#740)

Choosing **Reply** on a message changed nothing the assistant looked at,
so it kept the suggestions for the chat's last item. The page probe now
also hands over a hash of the message quoted above the message box, or
`-` for none, as a seventh field. It hashes what the quote shows, its
sender and text, never handing over the text, and ignores the quotes
inside message rows. The assistant names what it answers by that hash
too, so choosing a quote, or removing it with its ×, counts as a change.
Suggestions are made once per quoted message and cached under it, and
removing the quote shows the last item's suggestions from the cache.

The chat reader reads the quoted message as `replyingTo`, and the task,
never the cached chat, tells the model "I am replying to this message"
between `<reply-to>` tags, which `defused` keeps people's words from
closing.

The `composerQuote` landmark, `#main footer [data-testid="quoted-message"]`,
is a guess that has not been mapped on WhatsApp's own page yet; it must be
checked on the maintainer's session before merge. The fake WhatsApp page
gets the quote through the E2E helpers `chooseReply` and `removeReply`,
and an E2E test checks both ways.
