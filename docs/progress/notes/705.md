# Summaries of a chat's unread messages (#705)

Opening a chat with 10 or more unread messages summarizes them, with no
click, in a box hanging at the top of the chat, at its inline end:
**Writing the summary…** with the working light round its edge while the
model writes, then **Summary of N unread messages**: a plain list of at most six points,
anything that needs the user first and said plainly, such as a message
to them or a request for everyone to reply, or why none came, with **Try Again** when that may help. A close button
or Esc closes it; it never takes the focus, and the suggestions stay at
the bottom. WhatsApp marks messages read as the chat opens, so the follow
loop's look now also hands over the chat list's unread badges, as
`hash:count` pairs named by the same fingerprint as the open chat's
header, and the count is the badge's at the look before. A look also
runs as YapYap's window gets the focus, so a chat clicked from another
window still has its badge. A row's title holds more than the name, which
WhatsApp takes away as the row is hovered or opened, so rows are named
by `span[title]` alone (landmarks v13); the agents' open-chat and unread
readers read names that way too. WhatsApp draws
such a chat a row at a time, so a new last message no longer takes the
summary away. The request is the shared instructions, which gain a
section on summarizing, the chat context unchanged, then a task that
names the count and asks for the points fenced in `<summary>`; only
those are shown, as plain text. It runs only in chats the assistant
may read, once it is set up, and while the new **Summarize unread
messages** switch (`assistant.summaries`, on by default) is on. The
summary is held only in memory. **Mark all as read** is not offered:
opening the chat already marks the messages read.
